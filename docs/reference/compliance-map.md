# Compliance map

Maps repository controls to the obligations this project holds itself to. A change that touches a row below must say so in its pull request (gate 4). Changes that touch none of these are recorded as out of scope with a reason.

| Area | Obligation | Control in this repository | Evidence |
|------|------------|----------------------------|----------|
| Source integrity | Every policy entry is traceable to an official or openly licensed source (`SOURCE_ATTRIBUTION.md`). | `whitepaper_document_link` on `ai_policy_trackers`; PR template requires source table for data changes. | PR source table; `DataIntegrityTest`. |
| Change evidence | Edits to policy records are logged. | `a_i_policy_activity_logs` written by `AiPolicyActivityLogHelper` on create/update/delete. | Activity log rows per policy. |
| Personal data minimisation | Only data needed for the service is stored; no plaintext passwords. | `user_infos.password` column dropped (migration `2025_09_10_000000`); `UserInfo::$hidden`; admin-only user views. | Migration; `AdminAccessTest`. |
| Access control | Admin area restricted to configured accounts. | `ADMIN_EMAILS` + `CheckAdmin` middleware + `User::isAdmin()`. | `AdminAccessTest`. |
| Secrets handling | No secrets in the repository. | `.gitignore`, `.env.example` placeholders, GitHub secret scanning with push protection, App Service settings for runtime secrets. | Repository security settings. |
| Transport security | HTTPS only, secure cookies, security headers. | `SecurityHeaders` middleware; `SESSION_SECURE_COOKIE=true`; App Service HTTPS-only; Cloudflare TLS. | `curl -I https://aipolicytracker.org`. |
| Abuse resistance | Rate limits on authentication and write endpoints. | `LoginRequest` throttling; `throttle` middleware on notification route; Cloudflare in front. | Route definitions. |
| Vulnerability handling | Private reporting channel and automated scanning. | `SECURITY.md`; GitHub private vulnerability reporting; CodeQL; Dependabot. | Repository security tab. |
| Licensing | Software under Apache-2.0; third-party licences acknowledged. | `LICENSE`, `NOTICE`. | Files present. |
| Disclaimer | Content is informational, not legal advice. | README disclaimer; `SOURCE_ATTRIBUTION.md`. | Files present. |
| Source integrity (structured records) | Every policy-intelligence record links to an official source and shows verification state. | Source-quality columns on every factual table; `policy:validate` refuses records without `official_source_url`; `verified` requires `last_verified_at` and `reviewed_by`; UI shows "Human verification pending" until then. | `php artisan policy:validate`; `PublicSiteTest`. |
| Contributor data minimisation | Contributor submissions store only what review needs and are never public. | `contributor_submissions` readable only via `/backend/review` (`auth` + `isAdmin`); honeypot and throttle on `/contribute`; contact fields optional. | `PublicSiteTest::test_review_queue_is_admin_only_and_can_publish`. |
| Abuse resistance (public API) | Read-only public endpoints are rate limited and cannot write. | `throttle:120,1` on `/api/v1`; GET-only routes; responses cached. | `PublicSiteTest::test_public_api_is_read_only_and_cached`. |
| Disclaimer (site) | Every public page states informational-only, not legal advice. | Footer disclaimer in the public layout; `x-site.disclaimer` component on content pages; applicability tool labelled "educational screening only". | `PublicSiteTest` asserts the disclaimer on policy pages. |
| Analytics consent | Analytics scripts load only after consent when required. | `ANALYTICS_REQUIRE_CONSENT`; consent banner in `resources/js/public.js`; no third-party scripts before consent. | Layout and script. |
| Third-party data licences | External datasets are reproduced only within their licences with attribution. | `data/external/*.json` carry licence, citation and snapshot; `x-site.attribution` renders them on every page; report texts excluded. | `PublicSiteTest::test_ai_risk_and_incident_pages_render_with_attribution`. |
| Secrets at rest | Operator-entered API keys are never stored in plaintext. | `AppSetting::put` encrypts with `APP_KEY`; UI shows masked values only; `SubscriberAndSettingsTest` asserts the stored value does not contain the key. | Test. |
| Reading list stays on-device | Saved records never leave the browser. | `/saved` renders a shell; `resources/js/public.js` keeps `apt-saved` in `localStorage`; no route accepts the list. | `PublicSiteTest::test_subscribe_and_saved_pages_render_and_record_pages_carry_follow_and_save_controls`. |
| Download consent separation | Terms acceptance and marketing consent are separate, timestamped and never pre-ticked. | `users.terms_accepted_at` vs `users.marketing_consent_at`; register and download forms; `resource_downloads.terms_accepted_at`. | `PublicSiteTest::test_guides_page_filters_and_free_tools_gate_downloads_behind_a_free_account`. |
| Private files, signed delivery | Template files are never linked publicly; each link is signed, 30-minute and owner-bound. | `resources/downloads/` outside webroot; `tools.file` uses `signed` middleware and checks `user_id`. | Same test (unsigned 403, other user 404). |
| Browser hardening | Every response carries a nonce-based CSP and no server version. | `SecurityHeaders` middleware; `azure/nginx.conf` hides `X-Powered-By`. | `PublicSiteTest::test_security_headers_include_a_nonce_based_csp_and_hide_server_version`; `docs/reference/vapt-2026-09-11.md`. |
| Subscriber consent | Email is sent only after double opt-in; unsubscribe is one click. | `SubscribeController` confirm flow; `List-Unsubscribe` headers; honeypot and throttle on the form. | `SubscriberAndSettingsTest`. |
